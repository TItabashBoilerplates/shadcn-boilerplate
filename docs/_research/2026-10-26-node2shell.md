# Node2Shell と 2026 年 10 月の関連セキュリティ修正

調査日: 2026-10-26。公式アドバイザリとリポジトリの manifest / lockfile を照合した記録。

## Node.js

Node2Shell は CVE-2026-111497。攻撃者が制御する Brotli データを Node.js が展開すると、メモリ破壊から情報漏洩・コード実行につながる。受信リクエストだけでなく外部から取得したレスポンスも対象となる。

10 月 21 日の修正版は **22.23.4 / 24.22.1 / 26.12.1**。同時に TLS・DNS・HTTP Agent などの問題も修正される。Brotli のバージョン文字列だけでは cherry-pick による修正の有無を判定できないため、Node.js の修正版または配布元のバックポートの証拠で確認する。

変更前は `devenv.nix` の `pkgs.nodejs_24` が Node.js 24.21.0 を供給していた。nixpkgs-unstable の更新でも修正版に届かなかったため、公式バイナリ 24.22.1 を SHA-256 で固定した（macOS / Linux の arm64 / x64）。無関係なツールの更新を避け、nixpkgs lock は維持する。上流へ戻す際は、この配布定義を削除し、修正版を供給する lock と実行結果を確認する。稼働済みのプロセスも再起動が必要。

## Bun（2026-10-27 追加確認）

同じ CVE-2026-111497 は Bun に同梱される Google Brotli にも影響する。
[Bun 公式アドバイザリ](https://github.com/oven-sh/bun/security/advisories/GHSA-663w-cv8g-jj2p) は影響範囲を `>=1.0.21 <1.4.4`、修正版を **1.4.4** としている。
`fetch` は Brotli レスポンスを自動展開するため、公開サーバー用途に限った問題ではない。
前回の Node.js 更新時には Bun 1.4.2 が残っていたため、追加更新した。

- devenv: nixpkgs の Bun 導出を公式 1.4.4 の配布バイナリ・SHA-256 で上書き。既存の Linux の patchelf / macOS の署名処理を維持する。
- Frontend: `packageManager` を `bun@1.4.4`、`engines.bun` を `>=1.4.4` に変更。
- Claude Assistant workflow の `setup-bun` と、EAS の development / preview / production の Bun を 1.4.4 に固定。simulator は継承する。
- 別件の [HTTP/3 QPACK DoS](https://github.com/oven-sh/bun/security/advisories/GHSA-cf8x-9m69-3gg3)（`>=1.3.14 <1.4.4`）も同じ更新で修正される。リポジトリ内には HTTP/3 を有効化する構成を確認できなかった。
- `bun build --compile` の生成物はランタイムを埋め込むため再ビルドが必要。このリポジトリの調査対象には該当するビルド設定はなかった。

Python lock に `brotli` / `brotlicffi` / `curl_cffi`、構成に PHP / Envoy / Istio は見つからなかった。
Desktop の Cargo lock の Brotli は Rust 実装であり、Google の C 実装と名前だけで同一視しない。
sharp-libvips 1.3.4 の [公式 POSIX ビルド](https://github.com/lovell/sharp-libvips/blob/v1.3.4/build/posix.sh) は FreeType の Brotli を無効化している。Windows DLL や外部の配布先すべてについての安全性を保証する調査ではない。

macOS arm64 で **Bun 1.4.4 / Node.js v24.22.1** の実行を確認。
更新後の `build-frontend`、`unit-test`、`drizzle-validate` は成功。
前回追加した loader のテストは公開型 `Transformed.map: RawSourceMap` に合わせて、文字列として再 parse せずオブジェクトの sources を検証するよう訂正した。
CI は引き続き node-forge の未解決 1 件を検出する。リモート CI / EAS の実行・配布はしていない。

## Next.js / React

10 月 14 日の Next.js 修正版は **16.4.1 / 15.5.28**。Cache Components の typed array を介した RCE、画像最適化の upstream SVG 処理の RCE、Server Actions の DoS が対象。画像処理の修正版は `sharp >= 0.35.5`。

調査時の `frontend/bun.lock` は **next 16.4.2 / sharp 0.35.5** であり、この修正基準を満たしている。`frontend/apps/web/package.json` も `next: ^16.4.1` を指定する。

React の該当アドバイザリが対象とするのは `react-server-dom-webpack` / `react-server-dom-parcel` / `react-server-dom-turbopack`。修正版は **19.0.9 / 19.1.10 / 19.2.9 / 19.3.1**。`react` / `react-dom` が 19.2.3 であることだけをもって、この RSC 脆弱性の影響ありとは判定しない。Next.js 利用者は Next.js 自体の修正版を適用する。モバイルやデスクトップのクライアント描画の React をこの理由だけで更新する必要はない。

## 配布環境

- **Vercel managed Node.js**: major のみ指定可能で minor / patch は Vercel 管理。公式 Node2Shell bulletin は 22.x / 24.x の設定変更不要と説明する一方、10 月 24 日時点で修正版の rollout 中と記載。ローカルの更新だけでは本番の修正完了を証明できない。実際の配信環境・provider の修正状況を確認する。WAF は取得レスポンスをカバーしない。
- **自己管理の Node.js / CI**: 修正版へ更新し、再起動または再ビルド・再配布する。npm 依存の更新だけでは Node.js 本体の問題は直らない。
- **EAS Build**: `eas.json` の development / preview / production に `node: 24.22.1` を指定した。development-simulator は development から継承する。実際の実行版は次回 build log でも確認する。React Native アプリのランタイムとビルド用 Node.js は区別する。
- **backend-py**: `Dockerfile.vercel` は Python コンテナ。Node.js の更新と混同しない。共通 Brotli decoder の影響を調べる場合は実際の同梱ライブラリを別途照合する。

## 追加監査と運用

`devenv shell -- security-audit` で frontend / drizzle の両 lockfile を npm advisory データと照合する。
`ci-check` にも接続した。アドバイザリは lockfile と独立して変わるので監査 task はキャッシュしない。
`devenv shell -- security-fix` は互換範囲内の修正を適用する。差分確認とテストが必須。

frontend の初回監査は 15 件。body-parser 2.4.0、fast-uri 3.1.9、undici 7.30.1 / 8.12.2 への更新で 11 件を解消した。
初回修正後に残った frontend 4 件・drizzle 1 件について、追加対応を行った。監査の除外はしていない。

| 対象 | 追加対応 / 状態 |
|---|---|
| [node-forge / GHSA-86w9-cpqp-85rv](https://github.com/advisories/GHSA-86w9-cpqp-85rv)（high） | **未解決**。Expo CLI が使う 1.4.0。公式修正版は未公開。最新の親でも依存が残る |
| [Zod / GHSA-mrhx-c7xc-m3w5](https://github.com/advisories/GHSA-mrhx-c7xc-m3w5)（high） | **解消**。shadcn 4.22.1 は Zod 4 に移行済み。Expo CLI のみに `@expo/cli>zod: 4.6.7` を適用。実際のプラグイン検証・MCP コマンド schema・JSON Schema 変換・配列上限の早期拒否をテスト |
| [decode-uri-component / GHSA-vcc3-ghjq-m6fr](https://github.com/advisories/GHSA-vcc3-ghjq-m6fr)（moderate） | **解消**。query-string のみ 0.5.1 を使用。既存 CommonJS caller / Metro 用に `type` と export の2行だけ Bun patch で変更。デコード本体は上流修正版。正常な日本語・空白と大量の不正バイト列をテスト |
| [uuid / GHSA-w5hq-g745-h8pq](https://github.com/advisories/GHSA-w5hq-g745-h8pq)（moderate） | **解消**。xcode のみに CommonJS 対応の 11.1.1 を適用。Xcode ID 生成と v5 の不正 buffer 拒否をテスト |
| [esbuild / GHSA-67mh-4wv8-2f99](https://github.com/advisories/GHSA-67mh-4wv8-2f99)（moderate） | **解消**。@esbuild-kit/core-utils のみに 0.28.2 を適用。legacy loader 経由の TypeScript 変換・source map と `drizzle-validate` を確認 |

互換性 override は親の宣言範囲外なので回帰テストを残す。親が修正版に対応したら override / patch を削除する。
既存 node_modules には旧 Zod の nested install が残ったため、旧 tree を `.devenv/security-deps.*` に退避し、lockfile から再インストールして実際の解決先を検証した。

node-forge の [PR #1152](https://github.com/digitalbazaar/forge/pull/1152) に対しても [PR #1159](https://github.com/digitalbazaar/forge/pull/1159) が修正漏れを指摘している。未承認の暗号実装を取り込んで解決済みとは扱わない。公式修正の公開と Expo の対応を追従する。
ユーザー指示により boilerplate の CI 失敗を許容する（`PROJECT.md`）。監査は引き続き node-forge を検出して失敗する。
監査は Node.js 本体や Python / Rust / Deno の依存すべてを保証するものではない。
この雛形には本番 project の決定・接続情報がないため、本番の patch 適用済みとは判定していない。

## 検証結果

- macOS arm64 の `devenv shell` で Node.js v24.22.1 を確認。他 OS の実行確認は未実施。
- `build-frontend`: 5 task 成功。
- 初回の `unit-test`: 成功。Python（58 テスト）/ Edge Functions も成功。
- 追加修正後の `test-frontend`: 46 ファイル・519 テスト成功（既存の 4 skip）。`test-drizzle`: 19 テスト成功。
- `drizzle-validate`: 成功。DB マイグレーション生成・適用はしていない。
- `ci-check`: lint / format / 型チェックは成功。セキュリティ監査に残件があり失敗。
- 最終監査: frontend 1 件（node-forge / high）、drizzle 0 件。例外指定なし。
