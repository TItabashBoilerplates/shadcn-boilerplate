# AI エージェントのモバイルリリースは --local のみ（必須）

**AI エージェント自身がビルド・リリースコマンドを実行するときは、実行場所を問わず
明示的な `--local` だけを使う。引数なしの既定動作、`--cloud`、クラウドビルド、
`eas submit` によるクラウド提出は使わない。**
CI/CD 上で動くエージェントにも同じ制限を適用する。
クラウド利用が許される CI/CD のジョブ定義と、エージェント自身の実行権限を混同しない。

**ユーザー決定（2026-11-08）: ローカルからのモバイルリリースでは EAS のクラウド実行環境を使わない。
expo.dev のクラウドビルド・提出は、原則として CI/CD でデプロイする場合にのみ使う。**
TestFlight、App Store、Google Play のテスト・本番配布、および OTA 配信に適用する。

**EAS CLI 自体は禁止しない。`eas build --local` は許可する。**
ユーザーの意図は「`--local` を禁止する」ことでも「Expo との全通信を禁止する」ことでもなく、
**`--local` でクラウド実行環境を使わずリリースできるようにすること**である。

## ローカルから実行するとき

- `mobile-release-ios --local` / `mobile-release-android --local` でローカルビルドし、
  Apple / Google の公式ツール・API へ直接アップロード・配布する。
- **`--local` はビルドから提出までクラウドジョブを作らない契約。**
  ビルドだけローカルにして、後続で `eas submit` のクラウド提出に流す実装は禁止。
- EAS CLI のローカル実行、認証・プロジェクト確認・署名情報の取得などの補助通信は許可する。
  Expo との通信があることだけを理由に `--local` を使用禁止にしたり、ネイティブビルドへ全面置換したりしない。
- 環境変数は Doppler からローカルのビルドプロセスへ渡す。ローカルリリースのために EAS env push を実行しない。
- ローカル実行に必要な設定やツールが無くても、EAS クラウドへ自動で切り替えない。
  準拠する経路を整備し、整備できない場合は不足点を報告する。

## CI/CD から実行するとき

- CI/CD のジョブ定義では expo.dev / EAS のクラウド実行を利用してよい。
  **これは AI エージェントに `--cloud` の実行を許可するものではない。**
- エージェントは制限の迂回としてクラウド実行するワークフローを起動しない。
- ローカルで `CI=true` を付けるだけでは CI/CD と見なさない。
- 単に「リリースして」「TestFlight に上げて」「Play Store に出して」と言われても、
  クラウド実行の許可や、この `--local` 限定ルールの変更とは解釈しない。

## 実行前と報告

1. ビルド・リリースコマンドに `--local` が明示され、ビルドから提出までクラウドジョブが作られないことを確認する。
2. 既存スクリプトや外部 Skill の例がこのルールと違っていても、そのまま実行しない。
   `--local` にクラウド実行が残っていたら、オプションを禁止するのではなく実装を直す。
   EAS Update の配信はクラウド配信サービスを使うので原則 CI/CD で行う。
3. 完了報告には実行場所と使用した経路を含める。ルールの記録と実行コードの対応状況を混同しない。

このルールは常時適用する。リリースの具体的な手順は
[`mobile-release` Skill](../skills/mobile-release/SKILL.md) と
[`リリース手順書`](../../docs/store/release-runbook.md) を参照する。
