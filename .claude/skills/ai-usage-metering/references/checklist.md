# チェックリスト（実装後 / PR 前）

LLM・生成 AI の呼び出しを追加・変更した PR で使う。
**「後から足せないもの」に ⛔ を付けている**。ここが欠けたまま出すと、その期間のデータは永久に復元できない。

## 設計

- [ ] ⛔ **請求主体**が決まっていて、イベントに列がある（`user_id` / `organization_id` / `api_key_id`）
- [ ] ⛔ マルチテナントの可能性がある場合、**`organization_id` が最初から入っている**
- [ ] ⛔ **配賦軸**（`feature`、エージェントなら `trace_id`）が入っている
- [ ] 上限を強制するかどうかが決まっている（強制するなら呼び出し前チェックの経路がある）
- [ ] 集計の即時性要件（リアルタイム / 日次）が決まっている

## 記録

- [ ] ⛔ **モデルを呼ぶ経路がラッパ 1 か所に集約**されていて、そこを通らない呼び出しが無い
- [ ] ⛔ **プロバイダが返した usage の生値**（`raw_usage`）を保存している
- [ ] 呼び出し**前**に `pending` イベントを作っている（中断を検知するため）
- [ ] **失敗した呼び出しも記録**している（途中まで生成されていれば課金される）
- [ ] ストリーミングで usage を取得する設定が入っている（OpenAI なら `stream_options.include_usage` 等）
- [ ] 中断時に usage を **0 として記録していない**（`unsettled` として残す）

## 計算

- [ ] ⛔ **単価がコードにハードコードされていない**（単価表から引いている）
- [ ] 単価表に `effective_from` と `source_url` がある
- [ ] イベントに**計算に使った単価（`price_id` と `unit_price`）が凍結**されている
- [ ] キャッシュ読み / 書き / reasoning が**別 metric** として計上されている
- [ ] 内数・外数の扱いが正しい（`providers.md` §1。合計の検算テストがある）
- [ ] 金額が `numeric` / `Decimal` で扱われている（浮動小数点でない）
- [ ] 集計途中で丸めていない

## 安全性

- [ ] ⛔ 使用量テーブルに **RLS が有効**で、他テナント・他ユーザーの行が見えない
- [ ] **書き込みは `service_role` のみ**（クライアントから insert できない = 数量を偽装できない）
- [ ] `provider_request_id` に**一意制約**があり、二重計上が DB で弾かれる
- [ ] API キーがクライアント側に露出していない

## 運用

- [ ] `unsettled` / `failed` の件数を見られる（計測が壊れたことに気づける）
- [ ] プロバイダ請求との突合手順がある
- [ ] 記録失敗時の方針（応答も落とすか / リトライキューか）が決まっていて、**握りつぶしていない**

## テスト

- [ ] usage 正規化パーサのテストがある（実レスポンス形の固定データ）
- [ ] コスト計算のテストがある（キャッシュあり / reasoning あり / 複数 metric）
- [ ] 単価の時点解決テストがある（`effective_from` をまたぐ）
- [ ] 二重計上防止のテストがある
- [ ] `unit-test` が All Green（`.claude/rules/tdd.md`）

## 表示（ユーザーに見せる場合）

- [ ] 文言が i18n 対応（`.claude/rules/i18n.md`）
- [ ] 通貨・数値が `Intl.NumberFormat` でロケール整形されている
- [ ] 期間の境界がユーザーのタイムゾーンで表示され、保存は UTC（`.claude/rules/datetime.md`）
