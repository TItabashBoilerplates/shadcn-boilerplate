# List Pagination Policy

**MANDATORY**: **件数が増えうる一覧は、開発者からの指示を待たずに最初からページングを実装する。**
UI パターン（ページ番号 / もっと見る / 無限スクロール）も**エージェント自身が選定する**。
「今はデータが少ない」は理由にならない（seed では顕在化せず、本番でレコードが増えてから壊れる）。

正典: `/.claude/rules/list-pagination.md`

## 適用判定（一覧を書く前に）

以下のどれかが「はい」ならページング必須:

1. 時間の経過で行が増えるか（投稿・注文・ログ・通知・履歴）
2. ユーザー / テナントが増えると行が増えるか
3. 外部連携（インポート・同期・Webhook）で行が入るか
4. 件数上限がスキーマ / 仕様で**ハードに保証されていない**か

保証されている場合のみページング UI 不要。ただし `limit` は必ず付け、根拠をコメントに残す。

## 原則

- **全件取得の禁止**。一覧クエリには必ず `limit` / `range` を付ける。
- **ページングは常に DB 側**。クライアントの `slice` / `filter` による擬似ページング禁止。
- **API の `limit` はサーバー側でクランプ**（既定 20 / 最大 100 など）。
- `PAGE_SIZE` とページャ UI は**共有化**（画面ごとのコピペ禁止 → clean-code）。

## UI パターンの既定

| 画面の性格 | 既定 |
|---|---|
| Web 管理画面 / データテーブル / 検索結果（目的志向） | **ページ番号 + URL 同期**（`?page=`） |
| Web 公開一覧で SEO・共有が要る | **ページ番号 + URL 同期** |
| Web の探索的グリッド / ギャラリー | **「もっと見る」ボタン** |
| Mobile（Expo / RN）のリスト | **無限スクロール**（`onEndReached` + 仮想化リスト） |
| チャット / タイムライン / 通知（新着が前方に挿入） | **カーソル(keyset)ページング** |

**迷ったら「もっと見る」**（フッターに到達でき、キーボードで進め、後からどちらにも移行できる）。

無限スクロールの必須条件（1 つでも欠けたら「もっと見る」にする）:
フッターが無い / 「もっと見る」ボタンを DOM に残す（キーボード fallback）/ スクロール位置を復元できる /
読み込み中・末尾・失敗が判別できる。

> SEO 対象の一覧を「もっと見る」や無限スクロールだけで構成しない。Google のクローラは
> **ユーザー操作を要する JS を実行しない**ため、各ページが `<a href>` で辿れる実 URL を持つこと。

## データ層

- `order` には**必ず一意列の tiebreaker**（`.order('created_at', …).order('id', …)`）。無いとページ間で重複・欠落。
- ページ番号 UI → `range()`（offset）。無限スクロール / フィード / 新着が前方挿入 → **keyset(cursor)**。
- ソートキー（＋テナント列）に**複合 index**を張る（Drizzle スキーマ側）。
- `count` は総数を UI に出すときだけ取る。大テーブルは `count: 'estimated'`。
- API レスポンスは次ページの取り方を自身で示す（`nextCursor` / `page` + `pageSize` + `total`）。

## 必須 UI 状態

初回ローディング（Skeleton）/ 追加ローディング / 空（次のアクション付き）/ エラー（ログ + 再試行、
空配列フォールバック禁止）/ 末尾到達 の 5 つ。文言はすべて next-intl（en / ja）。

## 禁止パターン

```ts
await supabase.from('orders').select('*')                 // 全件取得
allRows.slice((page - 1) * 20, page * 20)                 // クライアント擬似ページング
const [page, setPage] = useState(1)                       // ページ状態を URL に持たない
.order('created_at', { ascending: false }).range(from, to) // tiebreaker 無し
catch { return [] }                                        // 失敗を 0 件として表示
```
